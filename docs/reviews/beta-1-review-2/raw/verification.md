Verifier: server-review agent. Findings below were supplied by the parent and checked independently against current source and installed dependency code. This verifier did not author the original mobile finding.

## Offline sharing pause never reaches its local pause code

- Verdict: confirmed, high severity, must fix before beta.
- Category: bug with privacy consequences and a blocking UX state.
- Primary locations: `apps/mobile/components/LocationSharingCard.tsx:108` and `apps/mobile/components/LocationSharingCard.tsx:123`.
- Related locations: `apps/mobile/lib/api.ts:30`, `apps/mobile/lib/networkStatus.ts:41`, `apps/mobile/lib/locationSharing.ts:281`, `apps/mobile/components/LocationSharingCard.tsx:255` and `apps/mobile/components/LocationSharingCard.tsx:277`.
- Independent source trace: the root layout mounts OfflineBanner, which calls useOfflineStatus and immediately sets TanStack onlineManager false for a known offline connection. LocationSharingCard wraps changeLocationSharing in useMutation without a networkMode override. The shared QueryClient config only sets query defaults, leaving mutations on TanStack's default online mode. The installed query-core `retryer.ts:53` returns onlineManager.isOnline() for that mode; `mutation.ts:178` invokes mutationFn only after the retryer starts. Therefore changeLocationSharing is not called while offline. Its durable pending write and immediate native pause are inside mutationFn, so neither happens. Meanwhile isPending disables Cancel and the modal close handler, leaving the person stuck until connectivity returns or the app is restarted.
- Independent execution: `/tmp/beta2-independent-offline-pause-probe.ts` uses the installed query-core QueryClient and MutationObserver with matching default options and a local side-effect counter. Saved output: `tooling/offline-mutation-independent-probe.log`. Offline result is `{phase:"offline",localSideEffects:0,status:"pending",isPaused:true}`. After onlineManager becomes true, the side effect runs and the mutation succeeds. This reproduces the scheduler behavior without mobile mocks. It is not an Android device demonstration.
- Failure scenario: with sharing already enabled, lose connectivity, open the pause modal and confirm a pause of this phone or all devices. Native capture keeps running; no durable pause is queued. Cancel/backdrop/Android back cannot close the modal. The request has no timeout because it never reaches the bounded tRPC client. If the app exits before reconnecting, the unpersisted mutation disappears and the pause never occurs.
- Scope restraint: this does not show locations reaching the server during an outage. It proves ongoing local capture, lack of a durable pause and an indefinite UI wait. On reconnect, the existing background uploader and delayed pause have no demonstrated ordering guarantee; do not claim a specific leaked point without a device/race reproduction.
- Suggested fix: run the local sharing mutation regardless of TanStack connectivity, for example `networkMode: "always"` on this mutation, preserving the helper's bounded transport, durable pending state and local native pause. Add a regression using the real QueryClient/MutationObserver or rendered component with onlineManager false; assert local pause happens before network recovery and the modal can finish. Audit other mutations with local side effects under the same policy, without globally enabling always mode for server-only mutations.
- Existing test gap: LocationSharingCard.test.tsx mocks useMutation with mutateAsync that immediately executes custom behavior and therefore cannot exercise TanStack's offline scheduler.
