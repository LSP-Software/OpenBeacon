# Second beta review: resolution checklist

Branch `t3/resolve-beta-review-findings`, based on `caccd60e` (the reviewed commit; `main` had not moved). Review documents were copied from the review worktree, where they were uncommitted.

Evidence classes used below:

- **Reproduced**: the failure runs against real code (probe or test).
- **Fault injection**: the control flow fails when a dependency is forced to stall or reorder; the platform doing that is unproven.
- **Source**: established by reading code paths; no execution.
- **Deployment check**: depends on provider/CDN configuration this repo cannot prove.
- **Accepted limit**: an existing documented decision, not a defect.

### Compatibility assessment

Levels stay 4/4/4. `API compatibility: unchanged`.

- **New app, old server (0.17.0):** no new procedure or input is used. The app still sends `Content-Type: image/webp`, which an old server ignores. Offline sharing replays through the existing `setLocationSharing`. Old servers keep SR-01/02/05 behaviour, which is server-side only.
- **Old app (1.13.0), new server:** shared-code refusals use the existing `NOT_FOUND` "Invite is invalid or expired", which old apps already handle. Old apps already PUT with `Content-Type: image/webp` and upload WebP from `EditableImage`, so the signed header and the WebP check accept them. These narrow behaviour no supported app relies on (rule 2 does not apply).
- **Encrypted formats:** none changed. CN-03 pins existing bytes.
- **Migrations:** none.
- **Deployment:** deploy order doesn't matter.

## Remaining risks and checks before beta

- **CDN headers:** add `X-Content-Type-Options: nosniff` and `Content-Disposition: inline` to image responses (a Cloudflare response-header rule). Whether a CDN would execute uploaded content stays unproven.
- **SecureStore:** checked on one emulator only, not on physical devices or other OEMs. A native operation that never settles now blocks later operations on that same key (each caller still gives up after 10 s). That is deliberate.
- **MOB-01:** "known offline" comes from `expo-network`. If the phone thinks it is online but requests fail, the bounded 30 s path applies; the sheet can still be dismissed.
- **Review paths:** local paths were stripped from `tooling/`, `raw/` and FINDINGS on this branch by rewriting its unpushed history. The uncommitted copy in the review worktree still has them.
- **Privacy wording:** AGENTS.md (CLAUDE.md) and the README now describe what the server can see. The docs site's landing hero ("Know where your family is. Nobody else does.") still overclaims; it is in the OpenBeacon-Docs repo, not changed here.
