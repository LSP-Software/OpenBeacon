# Second beta review: resolution checklist

Branch `t3/resolve-beta-review-findings`, based on `caccd60e` (the reviewed commit; `main` had not moved). Review documents were copied from the review worktree, where they were uncommitted.

Evidence classes used below:

- **Reproduced**: the failure runs against real code (probe or test).
- **Fault injection**: the control flow fails when a dependency is forced to stall or reorder; the platform doing that is unproven.
- **Source**: established by reading code paths; no execution.
- **Deployment check**: depends on provider/CDN configuration this repo cannot prove.
- **Accepted limit**: an existing documented decision, not a defect.

## Decisions (owner, 13 Nov 2026)

Prior decisions from `docs/reviews/beta-1/FINDINGS.md` stand: nothing has shipped, level 4 is the Beta 1 baseline, normal sign-out keeps keys, no infrastructure details in public docs.

| ID           | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| MOB-01       | Pause or resume of this phone or all devices while known offline: save the pending change, apply native state immediately, return `queued` without a network attempt; background replay sends it on reconnect. Pausing a different device offline fails at once with a connection message. Cancel/back/backdrop always close the dialog and never undo an applied local pause. Queued account-wide copy says other devices update when back online. Sharing mutations run with `networkMode: "always"`. Server-only mutations keep TanStack's default. |
| SR-01        | Keep the CLI. Preflight (sole ownership, image identity) refuses with nothing changed. The CLI then commits the same pending-deletion transition as the in-app request (deletionDate = now, sessions/invites removed) and runs the scheduled deletion. `deleteAccountRecords` repeats the preflight in its first locked transaction before payload batching. A later failure leaves the account pending and the job retries.                                                                                                                           |
| SR-02        | `acceptShared` requires the creator to be a current OWNER/ADMIN not pending deletion, under the Group lock. Also delete the creator's unused shared codes on removal, demotion to MEMBER, and self-leave. Five-minute bearer validity for a current admin's code is kept deliberately.                                                                                                                                                                                                                                                                 |
| SR-05        | Sign `content-type` (must be `image/webp`). On confirm require stored ContentType `image/webp` and a ranged-GET header check: RIFF/WEBP magic, a VP8/VP8L/VP8X first chunk, RIFF length matching object size. Otherwise delete and reject. No decoder dependency. `nosniff` and `Content-Disposition: inline` documented as a self-hosting deployment check. Separate upload origin not pursued. CDN script execution remains unproven (deployment check).                                                                                             |
| MOB-02       | Groups: first-load failure shows an error with Retry, never the empty state; refetch failure keeps data with a notice. Map: bounded signed-URL retries, then an error with Retry.
