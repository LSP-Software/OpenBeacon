# Android device support research

Research snapshot: 28 October 2026. This note records platform constraints and public adoption data; it does not certify any device or implementation as tested.

## Current Android use

[Statcounter's worldwide mobile Android version report](https://gs.statcounter.com/android-version-market-share/mobile/worldwide) for September 2026 shows Android 16 at 37.99%, 15 at 16.13%, 14 at 11.95%, 13 at 11.67%, 12 at 7.66%, and 11 at 6.14%. These top six sum to 91.54%. The figures are a web-traffic measurement, not a census of active devices, app users, installation eligibility, or phone ages. Regional and audience mixes can differ. Google's [Android Studio device distribution](https://developer.android.com/training/basics/supporting-devices/platforms) uses devices visiting Google Play and is a useful complementary check.

Five years before this snapshot is late 2021; Android 12 was released in October 2021, but a phone's launch date does not determine its installed OS or future updates. Android 11 and 12 devices are therefore meaningful minimum test candidates, not proof that every five-year-old phone is covered. [Android 12 release](https://developer.android.com/about/versions/12/overview).

## Location and background behavior

- A location foreground service is intended for long-running, user-visible location sharing, and must show a notification. On Android 10+ the service declares the `location` type; on Android 14+ when targeting API 34+, it additionally needs the appropriate foreground-service permission and location services plus coarse or fine location permission. [Foreground-service location type](https://developer.android.com/develop/background-work/services/fgs/service-types#location); [location permissions](https://developer.android.com/develop/sensors-and-location/location/permissions).
- Android 10 introduced background location permission. Android 11+ requires background location to be granted in settings; apps targeting API 30+ must request foreground and background location incrementally. [Android 10 privacy changes](https://developer.android.com/about/versions/10/privacy/changes); [Android 11 location changes](https://developer.android.com/about/versions/11/privacy/location).
- On Android 12+, a user can grant only approximate location even when precise is requested, and that limitation also applies to background location. Tests must include this choice. [Location permissions](https://developer.android.com/develop/sensors-and-location/location/permissions); [background location](https://developer.android.com/develop/sensors-and-location/location/permissions/background).
- On Android 12+, apps targeting API 31+ generally cannot start a foreground service from the background except under documented exemptions. On Android 14+, apps targeting API 34+ face additional while-in-use permission checks when creating a location service from the background. Background location access does not by itself remove the separate general restriction on background starts. Test starting from a visible activity, plus each intended recovery path. [Background-start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).
- Android 13+ adds notification runtime permission, but it is not required to start a foreground service; the service still needs a notification, which is visible in Task Manager if permission is denied. Android 13+ also lets users stop apps with foreground services through Task Manager. Test notification denial and explicit stopping. [Notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission); [user stopping](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping).
- Android documents additional background execution restrictions in the restricted battery state. Actual endurance and recovery should be tested on representative physical devices, including vendor-specific power management; an OS version alone cannot guarantee continuous tracking. [Android 13 background restrictions](https://developer.android.com/about/versions/13/behavior-changes-all#battery-resource-utilization).

## Distribution constraint

The minimum SDK determines installation eligibility; the target SDK controls behavior compatibility and Play submission policy. Google states that since 31 August 2026 new mobile apps and updates submitted to Play must target Android 16/API 36 or higher, with a possible extension until 1 November 2026. Targeting API 36 does not require raising the minimum SDK to 36. [Google Play target API requirements](https://developer.android.com/google/play/requirements/target-sdk).
